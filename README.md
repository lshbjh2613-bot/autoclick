# 서버 시간 예약 클릭

PC용 Chrome / Edge 확장 프로그램입니다. 사이트를 열어 직접 로그인하고, 페이지의 버튼을 선택한 뒤 **한국 시간(UTC+9)**으로 한 번 클릭을 예약합니다. 기본 주소는 [NOL 포스트시즌](https://nol.yanolja.com/ticket/genre/sports/postseason)입니다. 다른 HTTPS 사이트도 사용자가 해당 사이트 접근 권한을 허용하면 사용할 수 있습니다.

## 설치

1. 이 프로젝트를 PC에 다운로드하고 압축을 풉니다.
2. Chrome 주소창에 `chrome://extensions`를 입력합니다. Edge는 `edge://extensions`입니다.
3. **개발자 모드**를 켜고 **압축해제된 확장 프로그램을 로드합니다**를 누릅니다.
4. 프로젝트 안의 **`extension` 폴더**를 선택합니다. `manifest.json`이 들어 있는 폴더입니다.
5. 브라우저 도구 모음의 퍼즐 아이콘에서 **서버 시간 예약 클릭**을 고정하면 편합니다.

일반 사용에는 Node.js나 Python 설치가 필요 없습니다. 스마트폰 브라우저는 지원하지 않습니다.

## 버튼 위치 찾기와 예약

1. 확장 프로그램을 열고 **사이트 주소 → 주소 열기**를 누릅니다. 필요한 사이트 접근 권한을 허용합니다.
2. 열린 사이트에서 직접 로그인하고 실제 누를 버튼이 있는 페이지까지 이동합니다. 로그인 상태는 브라우저가 관리하며 확장 프로그램은 비밀번호를 저장하지 않습니다.
3. 확장 프로그램의 **① 페이지에서 버튼 선택**을 누릅니다. 팝업이 닫히면 마우스를 버튼 위로 옮깁니다. 빨간 테두리를 확인하고 클릭합니다. **이 선택 클릭은 사이트에 전달되지 않습니다.** Esc로 선택을 종료할 수 있습니다.
4. 확장 프로그램을 다시 열면 선택한 버튼의 문구와 CSS 선택자가 표시됩니다. 원치 않은 요소를 골랐다면 다시 선택합니다. 화면 좌표를 입력할 필요는 없습니다.
5. **② 서버 시간 측정**을 누릅니다. 성공하면 보정 시각, PC와의 차이, 왕복 지연(RTT), 추정 시간 오차가 표시됩니다. 실패하면 예약할 수 없습니다.
6. 목표 날짜·시·분·초를 **한국 시간**으로 입력합니다. 사용 중인 PC의 시간대와 무관합니다. 예: 한국 시각 2026년 11월 3일 오후 2시는 `2026-11-03 14:00:00`입니다.
7. **③ 한 번 클릭 예약**을 누르고 팝업을 닫습니다. 페이지 오른쪽 아래 상태 표시를 확인합니다. 보정된 현재 시각으로부터 **3초 뒤 ~ 10분 이내**만 예약할 수 있고, 예약 직전 시간 측정은 2분 이내여야 합니다.
8. **대상 탭을 화면에 표시하고 PC를 켜 둡니다.** 다른 탭으로 이동하거나 창을 최소화하면 예약이 취소될 수 있습니다. 새로고침·탐색 후에는 다시 선택하고 측정해야 합니다.
9. 취소하려면 페이지 오른쪽 아래 **취소 / 선택 종료** 또는 확장 프로그램의 **예약 취소**를 누릅니다.

일반 모드에서는 버튼이 현재 비활성화되어 있어도 선택·예약은 가능합니다. 실행 시점에 여전히 비활성화 상태이면 클릭하지 않습니다. 버튼의 문구·링크·구조가 바뀌면 다시 선택해야 합니다. 카운트다운 영역에는 아래 대기 모드를 사용하세요. iframe 및 Shadow DOM 안의 버튼은 현재 지원하지 않습니다.

### 화면 버튼 활성화 즉시 클릭 (v0.3.0 · 서버 시간 불필요)

**v0.3.1부터 지금 설정하고 14:00에 시작하도록 예약할 수 있습니다.** `감시 시작 예약 · 한국 시간`에 원하는 날짜와 `14:00:00`을 입력한 뒤 감시 시작 버튼을 누르세요. `지금부터 30분 뒤로 설정` 버튼도 제공합니다. 빈 값이면 지금 시작합니다. 시작 예약은 PC 현재 시각 기준 24시간 이내이며, 최대 30분 감시 시간은 예약한 시작 시각부터 계산합니다. 예: 13:30에 14:00 시작으로 예약하면 14:00 이전에는 클릭하지 않고, 14:00부터 14:30까지 활성화를 감시합니다.

이 예약은 **PC 시계 기준**입니다. Windows의 `설정 → 시간 및 언어 → 날짜 및 시간 → 자동으로 시간 설정 → 지금 동기화`를 먼저 확인하세요. PC와 탭을 계속 켜 두어야 하며 절전·새로고침·탭 숨김 시 예약이 유지되지 않습니다. 예약 뒤 PC 시간이 크게 바뀌면 취소됩니다.

1. 해당 경기의 **예매하기 버튼 또는 남은시간 영역**을 선택합니다. **경기 확인**이 표시되면 원하는 경기인지 확인합니다.
2. **감시할 버튼 문구**를 실제 문구와 맞춥니다. 기본값은 `예매하기`입니다.
3. **활성화 즉시 감시 시작**을 누릅니다. 이 모드는 서버 시간 측정이나 목표 시각 입력 없이 최대 30분간 실행합니다. 따라서 서버 시간 측정이 캐시 오류로 실패해도 사용할 수 있습니다.
4. 페이지의 버튼 교체, 문구·disabled·class·style 변경 등을 `MutationObserver`로 감지해 실행 가능한 상태가 확인되면 같은 콜백에서 한 번 클릭합니다. 별도로 20ms를 기다리지 않습니다. CSS 애니메이션처럼 DOM 변경이 없는 활성화에는 렌더링 프레임 확인을 보완적으로 사용합니다.
5. 감시 중 탭을 화면에 유지하세요. 취소, 탭 숨김, 페이지 이동, 경기 정보 변경, 제한 시간 도달 시 중단합니다.

**이미 활성화된 파란색 예매하기 버튼이면 감시 시작 시각에 바로 클릭합니다.** 사이트가 버튼은 미리 활성화해 두고 서버에서만 오픈 시각을 검사한다면 이 모드가 오픈 시각을 알아낼 수는 없습니다. 14:00까지 기다리려면 감시 시작 예약에 시각을 입력하세요. 서버 시간 기준의 기존 시간 예약은 아래에서 별도로 제공하며 유효한 서버 시간 측정이 필요합니다. 0ms 처리나 서버 수신·대기열 진입 시각은 보장하지 않습니다.

### 남은시간이 00:00이 된 뒤 예매 버튼이 생기는 경우 (시간 예약 모드)

1. **① 페이지에서 버튼 선택**으로 해당 경기의 `남은시간 24:51` 같은 영역을 선택합니다. 내부 숫자만 눌러도 같은 문구의 바깥 영역을 찾아 등록합니다.
2. 확장 프로그램을 다시 열어 **경기 확인** 문구가 원하는 경기 제목인지 확인합니다. 스크린샷의 예라면 `2026 한국시리즈 2차전 KT vs 삼성`이 포함되어야 합니다. 넓은 페이지 전체나 다른 경기 정보가 잡히면 다시 선택하세요.
3. 서버 시간을 측정하고 목표 시각을 **예매 오픈 시각**으로 입력합니다. 예약은 오픈 10분 이내에 설정하세요.
4. **카운트다운 → 예매 버튼 활성화 대기**를 체크합니다. **활성화 후 버튼 문구**는 실제 문구와 맞춰 입력합니다. 기본값은 `예매하기`입니다.
5. 예약하면 목표 시각까지는 클릭하지 않습니다. 그 후 최대 10초 동안 같은 경기·같은 영역을 감시합니다. v0.3.0부터는 DOM 변경 감지 시 별도 20ms 대기 없이 확인하고, CSS만으로 보이게 되는 경우에는 주기적 확인으로 보완합니다. 카운트다운 문구가 변하거나 div가 button으로 교체되어도, 버튼 문구가 정확히 일치하고 활성화되었을 때 한 번 클릭합니다.
6. 경기 제목 등 주변 정보가 달라지거나 버튼 영역 구조가 달라지면 중단합니다. 버튼을 못 찾거나 계속 비활성화 상태이면 10초 후 종료합니다. 감시는 로컬 DOM 확인이며 사이트 요청이나 반복 클릭을 보내지 않습니다.

이 기능은 스크린샷에서 알 수 있는 전환 형태를 모의한 테스트로 검증했습니다. 실제 NOL의 HTML 구조나 활성화 후 문구가 다르면 재선택이나 추가 조정이 필요할 수 있습니다.

업데이트하려면 새 ZIP을 다른 폴더에 압축 해제하고 기존 확장 프로그램을 제거한 뒤 새 `extension` 폴더를 로드하거나, 기존 폴더를 덮어쓴 뒤 확장 관리 화면에서 새로고침합니다. 대상 NOL 페이지도 새로고침하고 버튼을 다시 선택합니다. 관리 화면에서 버전 **0.3.1**인지 확인하세요.

버튼의 선택자를 직접 확인하고 싶다면 Chrome에서 버튼을 우클릭 → **검사** → 개발자 도구에서 해당 요소 우클릭 → **Copy → Copy selector**를 사용합니다. 이 버전은 선택자를 붙여 넣는 대신 위의 시각적 선택으로 등록합니다.

## 시간과 실제 사이트 동작의 한계

네이비즘과 현재 방식의 비교 범위·접속 제한·정확도 해석은 [시간 정확도 검토](TIME_ACCURACY.md)를 참고하세요.

- HTTPS HEAD 응답을 5회 측정하고, 성공한 측정이 3회 이상이면 RTT가 가장 작은 값을 사용합니다. PC 시간과 응답 중간 시각의 차이로 보정합니다. `Age > 0`인 캐시 응답과 리디렉션 응답은 거절합니다. 로그인 정보를 시간 조회 요청에 보내지 않습니다.
- HTTP `Date`는 **초 단위**입니다. 해당 초의 중간을 추정하므로 최소 ±500ms에 네트워크 비대칭과 서버·CDN 차이가 더해집니다. 표시되는 오차는 전체 오차의 보증 범위가 아닙니다. 티켓 예매 시스템 내부 시간과 같은지는 알 수 없습니다.
- 목표 시각에 브라우저에서 `element.click()` 이벤트를 한 번 전달합니다. 서버 도착 시각, 예매 성공, 좌석 확보를 보장하지 않습니다. 이벤트 전달 메시지는 예매 성공 메시지가 아닙니다.
- 합성 클릭을 거부하거나 팝업에 사용자 제스처를 요구하는 사이트에서는 작동하지 않을 수 있습니다. CAPTCHA·대기열·사이트 제한을 우회하지 않습니다. 결제 및 후속 단계는 직접 확인해야 합니다.
- 탭 숨김, 페이지 이동, PC 시계 변경, 버튼 변경, 1초 이상 타이머 지연이 감지되면 실행하지 않습니다. 예약은 메모리에만 있어 브라우저 재시작이나 새로고침 후 복원되지 않습니다.
- 마지막 입력 주소, 목표 시각, 활성화 대기 옵션과 예약·즉시 감시 버튼 문구를 저장합니다. 선택한 버튼과 경기 확인 정보, 시간 보정은 현재 페이지 메모리에 보관합니다. 외부 수집 서버는 없습니다.

**검증 상태:** 시간 계산·DOM·백그라운드 측정 자동 테스트와 모의 HTTPS 페이지를 사용한 실제 Chromium 콘텐츠 스크립트 테스트를 제공합니다. 클라우드 Chromium의 관리 정책이 확장 설치를 차단하므로 확장 프로그램을 설치한 전체 흐름은 검증하지 못했습니다. NOL 접속도 프록시 정책의 403 응답으로 차단되어 **실제 NOL 페이지의 헤더·버튼·예매 동작은 검증하지 못했습니다.** 실전 예약 전에 무해한 버튼으로 시험하세요. Edge는 별도 실행 검증 전입니다.

## 개발과 테스트

Node.js 24에서 검증했습니다.

```sh
cd /workspace/autoclick
npm ci --ignore-scripts
npm test
npm run test:browser
```

PC에서는 프로젝트 폴더로 이동한 후 실행합니다. 브라우저 테스트는 설치된 Chromium을 사용합니다. 기본 경로는 `/usr/bin/chromium`이며 다른 경로는 `CHROMIUM_PATH` 환경 변수로 지정합니다. 브라우저는 테스트용 임시 프로필을 사용하고 테스트 후 삭제합니다. 실사이트 예매 요청을 보내지 않고 HTTPS 응답을 모의합니다.

확장 프로그램 코드를 수정한 뒤 확장 프로그램 관리 화면에서 **새로고침**하고 대상 사이트도 새로고침합니다. 별도 웹 서버나 빌드 과정은 필요 없습니다.
